## 2. Detailed Discrepancies & Mismatch Analysis

### 1. Endpoint & URL Mismatch
- **Issue**: `src/pages/shop.astro` directly fetches `https://ni-engineering-backend.onrender.com/api/v1/orders` using an inline script string rather than importing the modular `placeServerOrder()` from `src/lib/api/orders.ts`.
- **Issue**: `src/components/ContactForm.astro` posts to `/api/v1/contact` (relative URL), which will fail when the Astro static frontend is hosted on `https://niengineeringbd.com` and the Laravel API is hosted on `https://api.niengineeringbd.com`.
- **Fix**: Direct all frontend components to use `src/lib/api/client.ts` which respects `PUBLIC_API_URL`.

### 2. Envelope & Response Format Mismatch
- **Issue**: `ProductController`, `CategoryController`, `CartController`, `OrderController`, and `ContactController` return standard envelope `{ "success": true, "data": ... }`.
- In contrast, `BlogPostController`, `ProjectController`, and `SiteSettingController` return raw `{ "data": ... }` without the `"success": true` boolean.
- **Fix**: Standardize `BlogPostController`, `ProjectController`, and `SiteSettingController` to return `{ "success": true, "data": ... }`.

### 3. Category Slug Schema Constraint Mismatch
- **Issue**: `ProductResource` (Filament Admin) sets `category_id`, but the underlying `products` table migration requires a non-null `category_slug`. If an admin saves a product through Filament without passing `category_slug`, SQLite/PostgreSQL throws `Integrity constraint violation: NOT NULL constraint failed: products.category_slug`.
- **Fix**: Add a `booted()` model hook in `App\Models\Product` to automatically synchronize `category_slug` and `category_name` whenever `category_id` changes.

### 4. CORS & Custom Headers
- **Issue**: Frontend API client sends `X-Cart-Session` header for guest carts. Laravel 12 reverse proxy and CORS middleware must explicitly allow `X-Cart-Session` in `Access-Control-Allow-Headers` and `https://niengineeringbd.com` in `Access-Control-Allow-Origin`.

### 5. IDOR Vulnerability in Public Order Tracking
- **Issue**: `GET /api/v1/orders/{order_number}` currently returns full customer names and addresses if the `phone` query parameter is omitted.
- **Fix**: Require `phone` matching or return a redacted/masked payload when queried publicly without customer session authentication.
